## LinkedIn

I’ve been building **Throughline**, an open-source research operating system based on a simple principle:

**AI can help with research, but it should not silently become the calculator.**

A common research workflow ends up fragmented across papers, datasets, notebooks, charts, slides, and AI conversations. By the time a conclusion is written down, the path back to the underlying evidence can be surprisingly difficult to reconstruct.

Throughline is designed to keep that chain intact:

**sources → datasets → recorded analysis → validation → findings → figures/reports**

The goal is not just to generate an answer. It is to preserve the evidence, lineage, computation, and validation behind the answer.

A few design choices I care about:

- numerical results come from deterministic scientific computation
- AI assistance is optional and explicit
- core workflows are local-first
- missing evidence remains missing instead of being turned into certainty
- figures and reports remain connected to the research record
- the project is fully open source under Apache 2.0

I’m looking for researchers and engineers willing to try it and tell me where it fails.

GitHub: https://github.com/SarthakPattnaik1/throughline-os

Hi HN — I’ve been building Throughline, a local-first open-source research workspace.

The core idea is that a paper, dataset, analysis, validation step, finding, and figure should not become disconnected artifacts.

Throughline keeps those objects linked so a conclusion can be traced back to the evidence and recorded computation that produced it.

Language models can assist with reading and interpretation, but numerical results are produced by deterministic scientific code. Hosted AI is optional; the core workflow can run locally.

The current dataset-first workflow runs end to end, and the repository includes the architecture, release process, security model, and test suite rather than hiding those behind a hosted product.

I’d especially value feedback on:

- whether the evidence/provenance model is actually useful to researchers
- places where the local-first architecture is too complicated
- statistical/reproducibility assumptions that should be challenged
- workflows researchers would expect that are still missing
